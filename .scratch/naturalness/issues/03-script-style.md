# 대본을 어떤 말투와 길이로 쓸지

Type: grilling
Status: closed
Assignee: Ling (session 03)
Blocked by:
Map: [map.md](../map.md)

## Question

소개 대본이 "읽는 글"이 아니라 "말"로 들리게 하려면 무엇을 바꿀지 정한다.
- 어미: 해요체 / 습니다체 / 섞기
- 첫 인사에서 "저는 Ling의 AI 아바타로…"라고 밝힐지
- 구간 수(지금 14개)와 한 문장 길이, 작품 나열 방식
- 입버릇·연결어("사실", "근데")를 넣을지, 넣는다면 어느 정도
- 대본을 다시 생성할지, 지금 대본(Who am I 내용 반영본)을 손질할지

## Resolution (2026-10-29, Ling과 grilling)

1. **어미** (리허설 후 수정): 해요체와 습니다체를 섞는다. 사실·작품 소개는 습니다("…를 만들었습니다"), 느낌·개인 경험은 요("…가 제일 어려웠어요"). 같은 어미가 3번 넘게 이어지지 않게 하고, 비율은 대략 반반. "~노력했습니다/~경험하곤 합니다" 같은 보고서 어미는 계속 쓰지 않는다.
2. **AI 아바타 고지**: 뺀다. 첫 문장부터 Ling 본인으로 말한다("안녕하세요, Ling이에요"). Q&A 프롬프트의 "자기소개는 이미 했으므로…" 문장도 함께 고친다.
3. **길이·구간**: 발표 전체 **최소 10분**(Ling의 제약). 목표 약 4,300자(약 11분). 5주차 3구간을 1구간으로 합치고 나머지는 그대로 두어 **12구간**.
4. **문장·나열** (리허설 후 수정, "40자 이내" 규칙은 짧은 문장만 이어져 딱딱하게 들려서 폐기): 대부분의 문장은 40~80자로 하고, "-고, -는데, -서, -다 보니"로 생각 두 개를 한 문장에 잇는다. 사이사이에 20자 안팎의 짧은 문장을 넣어 리듬을 만든다(긴 문장 2~3개 + 짧은 문장 1개). 한 문장에 작품을 셋 이상 나열하지 않는다. 대표작만 깊게 말하고 나머지는 이름만 짧게 언급한다.
   - 대본: 『진회영(秦淮影)』. 사이트에 감독 설명이 있다(아버지와 '나'의 장면만 핸드헬드, 나머지는 고정 카메라로 감정을 절제).
   - 영상: 『가면』. 정전 단편은 정식 제목 『飞人乔丹』을 넣는다.
   - 게임: 『모탈리티 클로즈』.
   - 『우리만의 시간』(AI가 가족처럼 곁에 있는 이야기)은 마무리의 AI 주제에서 한 번 언급한다.
5. **늘어나는 분량**: 대표작마다 비하인드(왜 만들었는지, 무엇이 어려웠는지) 2~3문장. 마무리에 "AI와 저자성" 2~3문장을 더해 발표 전체를 꿰는 주제로 삼는다.
6. **비하인드 출처**: 지어내지 않는다. 사이트에 적힌 사실과 Ling이 직접 준 경험만 쓴다. Ling이 준 내용:
   - 『가면』: 가장 어려웠던 점은 머릿속 생각을 영상으로 완벽하게 표현할 수 없었다는 것.
   - 『모탈리티 클로즈』: 게임을 한번 해 보고 싶어서 시작했다. 지금 가장 어려운 점은 하나의 이야기를 게임 메커니즘에 맞게 잘 쓰는 것.
   - 그 밖의 사이트 사실(조사 결과): 『밑바닥(底儿潮)』의 제목은 북방 방언에서 왔고, 『黑暗中的谛语』는 크툴루 구절과 영화 오마주가 있다. 수상·상영·러닝타임·역할 정보는 사이트에 없다.
7. **연결어**: "사실", "근데" 같은 말은 구간당 최대 1개. "음", "어"는 대본에 쓰지 않는다.
8. **다시 생성 vs 손질**: 다시 생성하지 않는다. 지금 대본(예전에 쓴 대본에 실행 카드대로 어미를 고친 판)을 손으로 고쳐 문장을 잇고 어미를 섞는다. 생성 프롬프트(`src/gemini.js` `IDENTITY`·`generateIntro`)의 "대략 40자 이내로 짧게" 규칙은 위 4번의 긴·짧은 문장 규칙으로 바꾸고, 1번 어미 규칙도 같이 반영해 다음 생성에 대비한다.

다른 티켓에 주는 영향:
- 어떤 목소리로 발표하고 답할지: 음성으로 만들 분량이 약 4,300자 / 12구간. 크레딧·한도를 계산할 때 쓴다.
- 화면과 말을 어떻게 맞출지: 페이지 이동은 11번.
