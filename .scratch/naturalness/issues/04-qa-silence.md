# 질문 후 침묵을 어떻게 채울지

Type: grilling
Status: closed
Assignee: Ling (session 04)
Blocked by:
Map: [map.md](../map.md)

## Question

질문을 보낸 뒤 답이 나오기까지 몇 초간 소리 없이 기다리는 시간을 어떻게 처리할지 정한다.
- 맞장구 짧은 음성("아, 네", "음…")을 미리 만들어 바로 재생할지
- 예상 질문을 미리 정하고 답변 음성까지 만들어 둘지
- 둘 다 / 하나만 / 다른 방법(예: 아바타 표정·말풍선만)
- 답변 길이(지금 2~5문장)를 줄일지

## Resolution

(2026-10-29, Ling과 grilling으로 결정)

1. **맞장구**: 발표 목소리로 미리 녹음한 짧은 음성 4~6개("아, 네.", "음, 좋은 질문이네요." 등). 질문을 보내는 즉시(마이크·입력창 모두, 0.3초 안) 하나를 재생하고, 같은 것이 연달아 나오지 않게 돌려 쓴다. 발표 당일 API 호출 0회.
2. **두 번째 맞장구**: 맞장구가 끝나고 1초가 지나도 답이 없으면 "잠깐만요, 정리해서 말씀드릴게요" 류를 한 번 재생(2개 녹음, 질문당 최대 1회). 그 뒤로는 말풍선만 유지.
3. **미리 만든 답변**: 예상 질문 5~8개의 답변 문장과 음성을 미리 만든다. Gemini는 맞는 답변을 고르기만 하고, 그 답변이 질문에 그대로 답이 될 때만 쓴다. 애매하면 실시간 답변.
4. **실시간 답변**: 2~5문장 → 1~3문장(핵심 한 문장 + 근거·예 1~2문장). 음성은 지금처럼 답변 전체를 한 번에 만들고, 문장별 분할은 하지 않음(TTS 하루 10회 한도).
5. **화면**: "생각 중" 말풍선·아바타 생각 상태는 유지하고, 말풍선 문구만 재생 중인 맞장구와 맞춘다.

이어지는 것:
- 예상 질문 목록과 답변 내용 → [예상 질문과 답변 내용 정하기](06-expected-questions.md)
- 맞장구·미리 만든 답변의 녹음은 목소리 결정([어떤 목소리로 발표하고 답할지](02-voice-choice.md)) 뒤 구현 때 진행
