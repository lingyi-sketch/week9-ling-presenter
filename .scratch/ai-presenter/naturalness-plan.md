# 자연스러움 개선 기획서 — "AI 같다"는 느낌 줄이기

기존 기획: [destination-and-requirements.md](destination-and-requirements.md)

## 목적지
이 문서를 기준으로 구현하고, 아래 「점검 항목」을 리허설에서 통과한 상태.
발표를 처음 보는 사람이 "녹음해 둔 사람 발표 같다"고 느끼는 것이 기준이다.

## 정해진 것 (2026-10-29)
| 항목 | 결정 |
|---|---|
| AI 고지 | 첫 인사의 "저는 Ling의 AI 아바타로…"를 **완전히 뺀다.** 처음부터 Ling 본인으로 말한다 |
| 말투 | **해요체 중심.** 강조·마무리에서만 습니다체를 섞는다 |
| 질의응답 침묵 | **맞장구 클립 + 예상 질문 미리 답변.** 지금 구조(녹음 → 답변 → TTS)는 유지 |
| 제약 | 무료 Gemini 한도 안(TTS 모델당 하루 10회). Windows·Mac 공통 |

## 현재 원인 (코드 기준)
| 증상 | 원인 | 위치 |
|---|---|---|
| 목소리 톤 | 구간(5~8문장)을 통째로 TTS. 말투 지시 없음(지시문을 소리 내 읽어서 제거함) | `gemini.js` `synthesize` |
| 대본 말투 | 프롬프트가 "구어체"만 요구 → 문어체·나열식 결과 | `gemini.js` `generateIntro`, `IDENTITY` |
| 질문 후 침묵 | 녹음 종료 → WAV 변환 → 답변(2~6초) → 답변 전체 TTS → 재생. 그동안 소리 없음 | `app.js` `ask` |
| 화면-말 타이밍 | 문장 시작을 글자 수 비율로 추정, 강조 요소는 그 순간 탐색(+0.7초) → 항상 늦음. 페이지 이동 때 1.2초 무음 | `app.js` `playWav`, `focusOn`, `goTo` |

## 1. 대본 말투 (API 추가 비용 없음)

`generateIntro`·`answerQuestion` 프롬프트를 바꾼다.

- `IDENTITY`: AI 아바타 고지 문장 삭제. "너는 Ling 본인이다"로.
- 말투 규칙 (예시 문장과 함께 넣는다 — 규칙만 주면 다시 문어체로 돌아감):
  - 해요체 기본. "~했습니다/~노력했습니다/~경험하곤 합니다" 같은 보고서 어미 금지
  - 한 문장 40자 안팎. 한 문장에 작품 3개 이상 나열 금지 → 한두 개만 골라 깊게, 나머지는 "이 밖에도 몇 편 더 있어요"
  - 말하는 사람의 연결어 사용: "근데", "사실", "그래서", "그러니까" (구간당 1~2개, 남발 금지)
  - 감상 대신 구체: "몰입했다" → 어떤 장면을 쓰다가 막혔는지·왜 바꿨는지
  - 청중에게 던지는 말은 구간당 최대 1번
  - 추상 수식어 금지 목록: "생생한 숨결", "깊은 몰입", "새로운 영화적 언어" 등
- **구간 끝 다리 문장**: 각 구간의 마지막 문장은 다음 페이지로 넘어가는 말("그럼 영상 쪽으로 가 볼게요")로 끝낸다. → 5번(페이지 이동)과 연결
- 구간 수를 14 → 약 10으로 줄인다 (같은 성격의 과제는 묶기). TTS 한도 절약 + 흐름이 덜 끊김
- 생성 후 **사람 손질 단계**를 기본 흐름에 넣는다: 설정 화면 대본 편집기에서 Ling이 직접 고친 뒤 음성을 만든다

## 2. 목소리 톤 (시험 호출 2~3회)

- **말투 지시를 다시 넣되, 읽히지 않는 형식으로**: Gemini TTS 프롬프트 가이드의 구조(오디오 프로필 / 장면 / 연출 메모 / `#### TRANSCRIPT` 아래 본문)를 써서, 지시는 따르고 본문만 읽는지 **시험 호출 1~2회로 확인**한다.
  - 연출 메모 예: "20대 대학원생이 교실에서 자기 작품을 소개한다. 편하고 따뜻하게, 문장 끝을 내리지 말고, 생각하며 말하듯 가끔 짧게 멈춘다."
  - 실패(지시를 읽음)하면: 지시 없이 본문만 보내고, 대신 문장부호로 호흡을 만든다(쉼표, "…", 문단 줄바꿈).
- 발표 음성·맞장구·예상 답변·실시간 답변이 **같은 목소리 + 같은 연출 메모**를 쓴다 (톤이 바뀌면 바로 티가 남).
- 목소리 후보(Leda 외 1~2개)를 같은 문장으로 비교하고 싶으면 → 시험 호출 몇 회 추가. 선택 사항.

## 3. 질문 후 침묵 — 맞장구 클립 (TTS 1회)

- 짧은 맞장구 8~10개: "아, 네.", "음…", "오, 그거 저도 고민 많이 했던 부분인데요.", "아 잠깐만요, 어디 있더라…" 등.
  질문 내용을 알기 전에 나오므로 **어떤 질문에도 맞는 말만** 쓴다.
- **한 번의 TTS 호출로 전부 만든다**: 줄바꿈과 긴 쉼으로 구분해 한꺼번에 합성 → WAV의 무음 구간으로 잘라 클립별 파일로 저장(`tts/fillers/*.wav`, preset에도 포함).
  - 잘린 개수가 예상과 다르면 실패 처리하고 다시 시도(또는 개수를 줄여서).
- 재생 규칙
  - 🎤를 놓는 순간(녹음 종료) 바로 맞장구 1개 재생. 직전 두 번 쓴 것은 제외
  - 답변이 맞장구보다 늦으면, 2.5초 넘게 비면 "생각하는" 짧은 클립("음…") 1개를 더. 그 이상은 아바타 동작(아래)으로 채움
  - 텍스트 질문·가리켜서 설명에도 동일하게 적용
- 생각하는 동안 아바타: 고개를 갸웃하고 시선을 페이지 쪽으로 돌림, 말풍선은 "…"만 (지금의 "질문을 듣고 생각 중이에요" 문구는 AI 같아서 삭제)

## 4. 질문 후 침묵 — 예상 질문 미리 답변 (TTS 2~3회)

- 예상 질문 10개 정도를 Gemini가 사이트 내용에서 뽑고, Ling이 설정 화면에서 고친다. 답변도 미리 생성 → 손질.
  - 예: "AI로 쓴 대본의 저자는 누구라고 생각하세요?", "가장 애착 가는 작품은?", "게임은 언제 완성돼요?"
- 답변 음성도 3번과 같은 방식으로 **여러 개를 한 호출로** 만들어 잘라 저장 (4~5개씩 2~3회).
- 실시간 질문 처리: `answerQuestion` 프롬프트에 예상 질문 목록(id + 질문)을 넣고, 응답 스키마에 `faqId`를 추가.
  - `faqId`가 있으면 → 저장된 답변 음성 즉시 재생 (TTS 대기 0초, 한도 0회)
  - 없으면 → 지금처럼 새로 답변 + TTS
- 답변 길이를 2~5문장 → **2~3문장**으로 줄인다. 말이 짧아야 대화처럼 들리고 TTS도 빨라진다.

## 5. 화면과 말의 타이밍 (API 추가 비용 없음)

- **실제 문장 경계 사용**: 저장된 발표 WAV에서 무음 구간을 로컬로 분석해 문장별 시작 시각을 구하고 `script.json`에 함께 저장(`sentenceTimes`). 글자 수 비율 추정은 경계를 못 찾았을 때의 예비로만.
- **강조 대상 미리 계산**: 대본 저장(또는 음성 만들기) 때 문장마다 강조할 요소를 미리 찾아 `script.json`에 저장(`focus`: 요소 텍스트 일부 또는 선택자). 발표 중에는 찾지 않고 바로 실행.
- **말보다 먼저 가리키기**: 문장 시작 약 0.3초 전에 스크롤·강조 시작, 아바타도 그때 이동. 스크롤 후 0.7초 대기 삭제.
- **페이지 이동을 말과 겹치기**: 구간 끝 다리 문장("영상 쪽으로 가 볼게요")이 나오는 동안 다음 페이지로 이동 시작. 지금의 이동 후 1.2초 무음 → 다음 구간은 페이지가 그려지면 바로 시작.
- 질의응답: 맞장구가 나오는 동안 관련 페이지로 이동해 두고, 답 첫 문장과 함께 강조.

## 6. 측정 (먼저 만든다)
- 질문 처리 단계별 시간을 상태 표시줄/로그에 기록: 녹음 종료 → 첫 소리(맞장구) → 답변 도착 → 답변 음성 시작.
  개선 전후를 숫자로 비교한다. 목표: **첫 소리 0.3초 이내, 답변 음성 시작 6초 이내(예상 질문은 3초 이내)**.
- 오늘 쓴 TTS 호출 수를 모델별로 세어 설정 화면에 표시 (태평양 시간 자정 기준 초기화).

## TTS 한도 계획 (모델당 하루 10회)
| 날 | 작업 | 호출 수 |
|---|---|---|
| 1일차 | 말투 지시 형식 시험 2회, 맞장구 1회, 발표 음성 약 7구간 | 약 10 |
| 2일차 | 발표 음성 나머지 약 3구간, 예상 답변 2~3회 | 약 6 |
| 발표 당일 | 소개·맞장구·예상 답변은 저장본 재생(0회). 새 질문만 1회씩 | 질문 수만큼 |

- 다른 TTS 모델로 넘어가면 목소리 결이 달라질 수 있으므로, **미리 만드는 음성은 한 모델로 통일**하고 대체 모델은 실시간 답변에만 쓴다.
- 대본을 고치면 그 구간 음성만 다시 만든다(지금도 문장 해시로 캐시됨). 대본 확정 전에는 음성을 만들지 않는다.
- 리허설에서 질의응답 연습은 「OS 기본 음성」 모드나 예상 질문 위주로 해서 한도를 아낀다.

## 구현 순서
1. 측정(6) — 지금 상태 숫자 기록
2. 대본 프롬프트(1) → 대본 재생성 → Ling 손질
3. TTS 연출 형식 시험(2) → 결정
4. 무음 분할 유틸 (3·4·5가 공유) → 맞장구 클립(3)
5. 화면 타이밍(5)
6. 예상 질문(4)
7. 발표 음성 생성 → preset 갱신 → 리허설

## 점검 항목
- [ ] 첫 인사에 "AI 아바타" 고지가 없고, 대본이 해요체이며 한 문장에 3개 넘는 나열이 없는가?
- [ ] 연출 메모가 소리 내 읽히지 않고, 발표·답변 목소리 톤이 같은가?
- [ ] 🎤를 놓은 뒤 0.3초 안에 맞장구가 나오고, 같은 맞장구가 연달아 나오지 않는가?
- [ ] 예상 질문을 하면 3초 안에 저장된 답변이 나오는가?
- [ ] 강조 표시가 해당 문장보다 먼저(또는 동시에) 뜨는가? 페이지 이동 때 1초 넘는 무음이 없는가?
- [ ] 발표 당일 소개 전체를 돌려도 TTS 호출 수가 0인가?
- [ ] Windows와 Mac에서 같은 preset으로 같은 소리가 나는가?

## 확인이 필요한 것 (구현 중 시험으로 결정)
- Gemini TTS가 연출 메모 형식을 읽지 않고 따르는지 (시험 1~2회)
- 한 번에 합성한 여러 문장이 무음으로 깔끔히 잘리는지 (맞장구 시험으로 확인)
