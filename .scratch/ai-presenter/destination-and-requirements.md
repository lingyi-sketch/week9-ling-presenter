# AI 포트폴리오 발표자 — 목적지와 요구사항

## 목적지 (기획이 끝났다는 것은?)
구현용 기획서가 있고, 이 문서를 기준으로 Claude Code가 앱을 만들고 점검할 수 있는 상태.

## 누가, 어떤 장면에서 쓰나
- **사용자**: 발표하는 학생(Ling). 교실 프로젝터 화면에 앱을 띄운다.
- **장면 1 — 소개**: 앱이 포트폴리오 사이트(https://my-new-portfolio-ling-d2f5.vercel.app/)를 띄우고,
  캐릭터 '링이'가 마우스를 따라다니며 사이트 내용을 **각색한 대화체**로 소개한다.
  소개하는 동안 해당 페이지(프로필 → 스크립트 → 영상 → 게임 → 과제)로 화면이 자동 이동한다.
- **장면 2 — 질의응답**: 학생·교수가 질문하면 마이크로 듣고, 사이트 내용을 근거로 답한다.

## 필수 조건
1. Windows와 Mac에서 모두 동작한다 (Electron 데스크톱 앱).
2. 홈페이지 텍스트를 그대로 낭독하지 않는다. LLM이 핵심을 재구성해 사람이 말하듯 소개한다.
3. 질문은 마이크(버튼을 누르고 말하기)로 받고, 텍스트 입력도 예비로 둔다.
4. 답변은 사이트 내용을 근거로 하며, 사이트에 없는 내용은 모른다고 말한다.
5. 캐릭터 머리 위 말풍선과 음성으로 함께 출력한다.
6. API 키는 코드에 넣지 않는다 (.env 또는 앱 설정 화면에서 입력).
7. 인터넷 연결이 있어야 동작한다 (LLM·사이트 읽기에 필요). 오프라인 동작은 목표가 아니다.

## 기술 결정
| 항목 | 결정 | 이유 |
|---|---|---|
| 앱 형태 | Electron | Windows·Mac 공통, 웹페이지를 앱 안에 띄우기 쉬움 |
| LLM | Google Gemini API (무료 등급, gemini-3.5-flash) | 무료 키로 소개문 생성·질의응답 가능. 모델이 붐비거나(503) 없어지면(404) 다른 flash 모델로 자동 대체 |
| 사이트 읽기 | 숨은 창으로 사이트 각 페이지를 열어 본문 텍스트 수집 → 캐시 | 사이트가 클라이언트 렌더링이라 HTML만으로는 내용이 안 보임 |
| 음성 출력 | Gemini TTS(자연스러운 목소리) → 실패 시 OS 기본 음성 | 무료 범위에서 품질 확보 + 안정성 |
| 음성 입력 | 마이크 녹음 → Gemini가 받아쓰기와 답변을 한 번에 | Electron에서는 브라우저 음성인식(Web Speech)이 동작하지 않음 |
| 캐릭터 | 직접 그린 SVG 캐릭터 '링이' (눈 깜빡임, 말할 때 입 움직임) | 저작권 문제 없는 오리지널 |

## 점검 항목
- [ ] 앱을 켜면 포트폴리오 사이트가 뜨고 캐릭터가 마우스를 따라다니는가?
- [ ] '소개 시작'을 누르면 각색된 대화체로 말하고, 말풍선이 함께 나오는가?
- [ ] 소개 중 해당 페이지로 화면이 이동하는가?
- [ ] '질문하기'를 누르고 말하면 사이트 내용을 근거로 답하는가?
- [ ] API 키가 없거나 틀리면 이해할 수 있는 안내가 나오는가?
